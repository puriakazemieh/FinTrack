## ۱. وضعیت فعلی — جمع‌بندی

پروژه از نظر پوشش فیچر تقریباً کامل است: **۲۴ ماژول `feature-share`** + ۵ ماژول
`feature-container` روی KMP/Compose Multiplatform با معماری MVI و Koin.
سیستم Feature-Toggle واقعی وجود دارد:

- `ToolFeature` (۲۳ مقدار) + ترجیح `PREF_DISABLED_TOOLS` (CSV)
- گیت‌شدن در `ToolsScreen.kt` با `.visibleIf(ToolFeature.X)`

**اصل ثابت این نقشه‌راه: هر فیچر جدید باید یک مقدار `ToolFeature` بگیرد و پشت توگل باشد.**

### دسته‌بندی وضعیت

| وضعیت | موارد |
|---|---|
| ✅ کامل | تراکنش، دسته، منبع، تگ، اشخاص، بودجه، هزینهٔ ثابت، خرید، یادداشت، هدف، قسط، بدهی، چک، رویداد، تقویم مالی، دستاورد، FAQ |
| 🟡 ناقص | خواندن پیامک بانکی (`sms-reader` هست ولی جریان تأیید/ثبت کامل نیست)، گزارش‌ها (نمودارهای محدود)، وب (واکنش‌گرا نیست) |
| 🔴 خراب | نرخ ارز/طلا، مبدل ارز، دارایی‌ها (همه به یک API وابسته‌اند)، «هوش مالی»، اخبار |
| ⚪ خاموش عمدی | Sync (`SyncConfig.enabled = false`) |

## ۲. ریشه‌یابی APIهای خراب

### ۲.۱ نرخ ارز / مبدل / دارایی — یک نقطهٔ شکست مشترک

مسیر داده: `AssetRepository.syncRates()` → `AssetRepositoryImpl` →
`TgjuService.getLatestRates()` → `call.tgju.org/ajax.json`.

tgju درخواست‌های برنامه‌ای را با anti-bot/محدودیت جغرافیایی بلاک می‌کند → پاسخ خالی →
هر سه بخش «در دسترس نیست» نشان می‌دهند.

**راه‌حل:**
1. یک لایهٔ `RateProvider` با چند منبع پشت‌سرهم (fallback chain): tgju با هدرهای مرورگر →
   منبع جایگزین ایرانی → منبع بین‌المللی برای ارزهای جهانی.
2. **کش نرخ‌ها در دیتابیس** (SQLDelight) با timestamp؛ UI همیشه آخرین نرخ کش‌شده را با
   برچسب «به‌روزرسانی: X» نشان دهد و هرگز خالی نماند.
3. در میان‌مدت: پروکسی روی ماژول `:server` (Ktor) که خودش نرخ‌ها را جمع می‌کند و
   کلاینت‌ها فقط از سرور خودمان می‌خوانند.

### ۲.۲ «هوش مالی» (AI Advisor)

`AIAdvisorViewModel` اصلاً API ندارد — یک **موتور قانون‌محور محلی** است که چون قاعده‌هایش
کم فعال می‌شوند، اغلب خالی می‌ماند.

**راه‌حل:** فاز اول غنی‌سازی قاعده‌ها (روند هزینه، انحراف بودجه، هشدار سررسید، الگوی
دسته‌ها). فاز دوم LLM اختیاری از طریق `:server` (کلید API سمت سرور، نه کلاینت) — پشت
`ToolFeature.AI_ADVISOR` و یک ترجیح جداگانهٔ «تحلیل ابری».

### ۲.۳ Sync

عمداً خاموش است: `SyncConfig.enabled = false`، آدرس placeholder (`10.0.2.2:8080`) و توکن
هاردکد. فعال‌سازی آن یک پروژهٔ کامل است (فاز P4)، نه یک باگ‌فیکس.

## ۳. بنچمارک رقبا (کافه‌بازار، ~۶۰ اپ)

> ⚠️ کافه‌بازار دسترسی خودکار را با HTTP 403 می‌بندد؛ اعداد نصب/امتیاز باید دستی از صفحهٔ
> هر اپ برداشته و این‌جا ثبت شود. دسته‌بندی زیر از شناخت بازار است.

### کهن‌الگوها

| کهن‌الگو | نمونه‌ها | درس برای FinTrack |
|---|---|---|
| پیامک‌محور (ثبت خودکار از SMS بانک) | رسینو، فانوس، جیبیفای، مانایا | **بزرگ‌ترین اهرم رشد** — ماژول `sms-reader` را کامل کن (فاز P1) |
| حسابداری سنتی/اصناف | هلو، پارمیس، محک، موج، آینو، ابرآیرون | فاکتور/انبار خارج از تمرکز ماست؛ ولی «گزارش چاپ/PDF» را می‌خواهند |
| سادهٔ روزمره | دخل‌وخرج، پول‌نگار، خرج‌نویس، Monefy | ورود سریع ≤۳ لمس؛ ویجت ثبت سریع |
| بدهی/طلب/چک | بده‌بستون، چک‌من، دفتر حساب | یادآور سررسید قوی + گزارش شخص‌محور (داریم، باید صیقل بخورد) |
| بین‌المللی | Money Manager، Cashew، Ivy Wallet، MyMoney | نمودارهای غنی، چندارزی، بک‌آپ ابری، تم‌های متنوع |
| نرخ بازار | (بخش نرخ در جیبیفای و مشابه‌ها) | نرخ لحظه‌ای + دارایی — بعد از رفع P0 مزیت ماست |

### «باید داشته‌ها» که هنوز نداریم یا ناقص‌اند
1. ثبت خودکار از پیامک بانک با صندوق تأیید (Inbox → Approve → Transaction)
2. نمودار دونات دسته‌ها + روند ماهانه + تقویم جریان نقدی در گزارش
3. خروجی PDF/Excel از گزارش‌ها
4. بک‌آپ/بازیابی ابری (فعلاً فقط فایل محلی)
5. چندارزی واقعی (ثبت تراکنش به ارز دوم با تبدیل خودکار)

## ۵. صفحه‌های جدید پیشنهادی
1. **صندوق پیامک** (P1) — لیست پیامک‌های شناسایی‌شده با کارت تأیید سریع.
2. **گزارش حرفه‌ای** (P2) — تب‌های دونات/روند/تقویم.
3. **خلاصهٔ ماه** (P3) — کارت‌های روایت‌محور + اشتراک‌گذاری تصویر.
4. **ورود/حساب کاربری** (P4) — فقط وقتی Sync روشن است.

## ۶. اصول عرضی
- هر فیچر جدید = یک `ToolFeature` + گیت `.visibleIf(...)`؛ پیش‌فرضِ فیچرهای آزمایشی: خاموش.
- هیچ صفحه‌ای نباید به‌خاطر شبکه خالی بماند — همیشه کش + برچسب زمان.
- کلید/توکن هرگز در کلاینت نباشد؛ همه از `:server`.
- قبل از merge هر فاز: `./gradlew assembleDebug` روی دستگاه (سندباکس CI بیلد اندروید ندارد).
