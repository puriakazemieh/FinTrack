۱۷ نوامبر ۲۰۲۶؛ AVD مستقل `FinTrack_QA_API31`، API 31، serial ثابت `emulator-5556`، تصویر `system-images;android-31;default;x86_64`، پروفایل Pixel 9 Pro XL، مسیر داده `D:/Android/FinTrackQA/avds/FinTrack_QA_API31.avd`. AVD قبلی API 35 و گوشی شخصی هدف این فرمان‌ها نبودند. boot، Package Manager، API، نام AVD و qemu قبل از نوشتن داده کنترل شدند؛ `qa31-ready.json`.

## آماده‌سازی

تصویر API 31 از قبل نصب بود. نسخهٔ جدید shim مربوط به SDK Manager در این سیستم برای bootstrap به 404 می‌رسید. اجرای مستقیم کلاس نصب‌شدهٔ `com.android.sdklib.tool.sdkmanager.SdkManagerCli` نسخهٔ 23.0 را برگرداند و AvdManager موجود، AVD مستقل را ساخت. داده و snapshot روی درایو D قرار دارند. آماده‌سازی نیازی به تغییر گوشی شخصی نداشت.

فهرست آنلاین تصاویر هنوز قابل دریافت کامل نبود: تلاش‌های manifest با I/O/timeout و دریافت ناقص 8779 بایت متوقف شدند؛ فایل ناقص نصب نشد. APIهای 24/26/33 از این طریق تأیید نشده‌اند و خانه‌های مربوط به QA-N10 بازند. وجود API 31 نصب‌شده برای ادامهٔ مستقل این اجرا کافی بود.

## N-03b · سوایپ روی قفل، دو جهت

نسخهٔ اصلاح مقصد یادداشت، با مبنای `38742f3c` و SHA-256 برابر `f843ceca27865868272580c9e1b0ee7d26d32c1f19a6aa912259935430492e0a`؛ فارسی و IRT. به‌جز تغییر مسیر یادداشت، کد رفتار SMS همان اصلاح N-01a بود.

پیش‌شرط: روی همین AVD مستقل PIN موقت ساخته شد، نمایش اعلان روی قفل فعال بود و `deviceLocked=1` قبل از هر عمل تأیید شد. نخستین تلاش پیش از پایان مهلت قفل متوقف شد؛ پس از تنظیم مهلت و انتظار برای قفل واقعی، سناریو اجرا شد.

| عمل از ورودی واقعی تلفنی امولاتور | انتظار | نتیجه و شاهد |
|---|---|---|
| SMS معتبر برداشت 180000 ریال کارت 2222؛ سوایپ چپ | حذف کارت بدون ثبت یا مصرف draft، قفل باز نشود | کارت 18000 تومان حذف شد؛ `lock-left.mp4`، تصاویر/XML قبل و بعد، `lock-left-after-trust.txt` با deviceLocked=1 |
| SMS تازه برداشت 190000 ریال همان کارت؛ سوایپ راست | همان رفتار برای کارت تازه | کارت 19000 تومان حذف شد؛ `lock-right.mp4`، تصاویر/XML قبل و بعد، `lock-right-after-trust.txt` با deviceLocked=1 |

تصاویر بررسی شدند؛ کارت خود FinTrack جدا از کارت برنامهٔ پیامک سیستم بود. سوایپ FinTrack، اعلان برنامهٔ SMS را حذف نکرد. `lock-data-proof.json` نشان داد فقط دو draft جدید 32 و 33 ایجاد شده‌اند، هر دو `isUsed=0` مانده‌اند، تراکنش‌ها، منابع، مانده‌ها و دادهٔ مالی قبلی تغییر نکرده‌اند. تغییر `android_metadata` ناشی از locale سیستمِ AVD مستقل است.

پس از آزمون، PIN برداشته و حالت عادی برای ادامهٔ آزمون‌ها آماده شد. در API 31، پاک‌کردن credential در حالت قفل می‌تواند همان صفحهٔ PIN را موقتاً نگه دارد؛ بازآزمایی UI تا راه‌اندازی مجدد و بررسی قفل باز پذیرفته نشد. اسکریپت آزمون برای دفعات بعد ابتدا با PIN خودش قفل را باز و سپس credential را پاک می‌کند.

شواهد در `.artifacts/fintrack-2026-11-17/qa31/` قرار دارند. N-03b فقط سوایپ SMS با PIN روی API 31 را می‌بندد؛ میان‌بر و هشت نوع دیگر، APIهای باقی‌مانده، صدای معتبر و تنظیمات خصوصی/مسدودسازی هنوز طبق QA-N1 تا QA-N10 مستقل‌اند.

## GitNexus در ادامهٔ اجرا

به‌روزرسانی incremental با خروج موفق و status ظاهراً current، بعضی متدهای NoteEditViewModel را بدون uid قابل بازیابی برگرداند؛ از آن برای تصمیم یا تیک استفاده نشد. بازسازی کامل با فرمان زیر متد `saveNote`، uid، caller و جریان‌های آن را بازگرداند؛ context و status schema 4 با runner جاری و incomplete_reasons خالی بررسی شدند. این یک راهکار اجرایی برای ایندکس این نسخه است؛ ادعای رفع کد داخلی GitNexus نیست.

```powershell
gitnexus.cmd analyze --index-only --pdg --force --wal-checkpoint-threshold 1073741824
```

تا پایان بازسازی هیچ خواندن هم‌زمان همان DB انجام نشود. پس از status/context، یک متد معلومِ فایل تغییرکرده نیز از context بررسی شود؛ نبودن uid متد موجود در سورس، نتیجهٔ «بدون وابستگی» نیست و نیاز به بازسازی کامل دارد. این احتیاط به پرامپت اجرا اضافه شد.
