# FIX-01b3 — تنظیم یادآور در فرم هزینهٔ ثابت

۲۵ نوامبر ۲۰۲۶؛ مبنا0f2bdcb5. این زیرتسک فرم تکمیل شد. کنترل تازهٔ Worker، تحویل اعلان و قرارداد ثبت/تکرار هزینه در FIX-01b، QA-N9 و FIX-02 باز هستند.

## تغییر

فرم جدید یادآور خاموش دارد. سوییچ از state و intent مشترک MVI عبور می‌کند؛ روشن‌کردن، تاریخ و ساعت را در Field و GlassCard موجود نمایش می‌دهد. تمام ردیف سوییچ هدف لمس حداقل48dp و role مناسب دارد. اولین زمان پیشنهادی یک ساعت بعد با دقت دقیقه است؛ خاموش/روشن زمان انتخابی را نگه می‌دارد. تاریخ و ساعت مستقل و با timezone محلی ترکیب می‌شوند، بنابراین انتخاب تاریخ، ساعت را دوباره جمع نمی‌کند. زمان تازهٔ گذشته با پیام resource رد می‌شود؛ ویرایش اطلاعات دیگرِ رکورد قدیمی، بدون تغییر تنظیم یادآور، به زمان جدید اجبار نمی‌شود.

state هنگام بارگذاری و هنگام بازسازی مدل، currencyCode، reminderEnabled و reminderTime را حفظ می‌کند؛ مسیر registerAsTransaction نیز همان دادهٔ فرم را حمل می‌کند، اما قرارداد مالی ثبت در FIX-02 هنوز باز است. عنوان اعلان از برچسب درست هزینهٔ ثابت و پیام از عنوان هزینه استفاده می‌کند. ویرایش نیز متن محلی‌شده را به usecase می‌فرستد. پسوند مبلغ هنگام ویرایش از واحد ذخیره‌شده و هنگام افزودن از تنظیم جاری طراحی قبلی می‌آید؛ سیاست مخزن برای واحد درج تغییر نکرده است.

انتخابگرهای شروع، پایان، تاریخ و ساعت یادآور یک MutableState مستقیم دارند. وضعیت بازِ تکراری کنار remember(open=true) حذف شد تا انصراف، بازشدن دوباره را مسدود نکند. کنترل‌های مشترک تاریخ/ساعت و الگوی Glass موجود استفاده شدند. جست‌وجوی skill برای progressive disclosure نتیجهٔ اختصاصی تأییدپذیر نداد؛ الگوی خود اپ مبنای پیاده‌سازی ماند. برچسب و خطا resource هستند؛ متن خطا برای منابع انگلیسی/آلمانی نیز افزوده شد ولی UI فقط فارسی آزموده شد.

## بازتولید معتبر و build

ابزار Android از repository واقعی و ViewModel واقعی فرم استفاده می‌کند. fixture ابتدا از مخزن درج می‌شود؛ چون insert واحد تنظیمات را اعمال می‌کند، پس از درج، رکورد USD با مسیر update واقعی آماده و USD/خاموش بودن آن صریحاً پیش از ویرایش بررسی می‌شود. اجرای اولیهٔ ابزار پیش از این اصلاح fixture، شاهد معتبر رگرسیون واحد پول نبود و مبنای پذیرش قرار نگرفت.

با fixture اصلاح‌شده، دو فایل فرم موقتاً با سورس HEAD0f2bdcb5 build شدند؛ آزمون ویرایش فقط توضیحات با Currency changed USD -> IRT شکست خورد. سورس اصلاح‌شده بلافاصله از snapshot دقیق بازگردانده و build شد. همان آزمون بدون تغییر assertion پاس شد: توضیحات ذخیره شد، USD، خاموش بودن، زمان صریح، startDate و nextDueDate حفظ شدند. اثر fixture پس از لغو واقعی job به دیتابیس/prefs اولیه با بایت دقیق بازگردانده شد.
