# پذیرش SMS-03 و تأیید شنیداری کاربر

۱۷ نوامبر ۲۰۲۶. SMS-03 دربارهٔ مقصد و اثر عملیات پیامک و میان‌بر است. این ردیف به اشتباه تا تکمیل ماتریس عمومی صدا/نسخه‌ها باز مانده بود؛ آن معیارها متعلق به QA-N1 تا QA-N10 هستند. پذیرش عملکرد این ردیف با شواهد زیر تجمیع شد؛ بازبودن آزمون عمومی به معنی اصلاح‌نشدن مسیر SMS نیست.

| عمل | نتیجهٔ پذیرفته‌شده | شاهد |
|---|---|---|
| لمس بدنهٔ SMS | فرم همان draft، مبلغ/واحد، متن و منبع درست؛ صرف بازکردن ثبت نمی‌کند | [SMS-03a](2026-11-17-fintrack-sms03a-results.md)، ردیف draft 26؛ [N-01a](2026-11-17-fintrack-notification-identity-results.md)، PendingIntent واقعی دو SMS هم‌عدد |
| ویرایش | همان draft با مبلغ و متن خودش در فرم باز می‌شود؛ خطا فرم را نمی‌بندد | SMS-03a، draft 27؛ [SMS-05b](2026-11-17-fintrack-sms05b-results.md)، فرم پیام 36 و خطای اتمی |
| ثبت | draft و روابط و مانده در یک تراکنش ثبت می‌شوند؛ retry/رقابت ثبت تکراری نمی‌سازد | [SMS-05a](2026-11-17-fintrack-sms05a-results.md)، SMS-05b ثبت تکی و گروهی؛ N-01a ثبت مالی واقعی و حذف کارت فقط پس از موفقیت |
| نادیده‌گرفتن | فقط draft همان پیام مصرف می‌شود؛ تراکنش ساخته نمی‌شود؛ کارت نوع دیگر و SMS هم‌عدد باقی می‌مانند | SMS-03a، draft 28؛ N-01a، Receiver واقعی با budget هم‌عدد |
| SMS مصرف‌شده | لینک قدیمی فرم ثبت تازه باز نمی‌کند | SMS-03a، used-cold؛ آزمون‌های ثبت اتمی SMS-05 |
| میان‌بر افزودن | فرم خالی باز می‌شود؛ سوایپ draft مالی نمی‌سازد و شروع سرد اعلان ردشده را برنمی‌گرداند | [نتیجهٔ عملکردی QA-N2](2026-11-16-fintrack-execution-results.md)، ردیف N-03/QA-N2؛ بدنه و اکشن در ناشر، PendingIntent مشترک همان فرم را دارند |
| سوایپ روی قفل | کارت کنار می‌رود، پیش‌نویس مصرف نمی‌شود و پرداخت/ثبت نمی‌سازد | N-03/SMS-03a روی API 35؛ [N-03b](2026-11-17-fintrack-android31-notification-results.md)، چپ و راست با PIN روی API 31 |

ارجاع [نتیجهٔ عملکردی QA-N1](2026-11-17-fintrack-sms03a-results.md) شامل SMS واقعی، بدنه، ویرایش، نادیده‌گرفتن و بنر است. این ارجاع به معنی بسته‌شدن تمام شرط‌های QA-N1 یا QA-N2 نیست. بازآزمایی ناشر و callback روی API 31 در `qa31/native.log`، **۹ تست و صفر failure** بود؛ شامل ثبت مالی واقعی. در همین بسته **۱۲۱ تست JVM، صفر failure/error** و build Android پاس شدند. اصلاح بعدی هدر فقط جای دو کنترل را عوض می‌کند و منطق ثبت یا Receiver را تغییر نمی‌دهد.

## تأیید صدای ۹ نوع اعلان

کاربر ابتدا گفت «شنیدم و می تونی ببندی». پس از توضیح اینکه آزمون عمومی علاوه بر صدا شامل بنر، سوایپ، قفل، مجوز و عملکرد هر ۹ نوع است، برای مشخص‌کردن دامنه پرسیده شد صدای کدام نوع اعلان شنیده شده است. پاسخ صریح کاربر: **«همه رو شنیدم»**.

| نوع | پذیرش شنیداری |
|---|---|
| پیامک بانکی | تأیید دستی کاربر |
| میان‌بر افزودن تراکنش | تأیید دستی کاربر |
| بودجه | تأیید دستی کاربر |
| قسط | تأیید دستی کاربر |

| بدهی و طلب | تأیید دستی کاربر |
| خرید | تأیید دستی کاربر |
| یادداشت | تأیید دستی کاربر |
| هزینهٔ ثابت | تأیید دستی کاربر |

QA-AUDIO بسته شد. مدل دستگاه و نسخهٔ اندروید در این تأیید اعلام نشده‌اند؛ شاهد، تأیید شنیداری کاربر است و از build، dumpsys یا ضبط بدون صدا استنتاج نشده است. نتیجه به همهٔ APIها تعمیم داده نمی‌شود. وضعیت کانال بی‌صدا/مسدود، DND، رد مجوز، دو اعلان هم‌زمان، بنر، اکشن‌ها و ارتقا طبق ردیف‌های مستقل باز می‌ماند.

برای بستن SMS-03 و بخش شنیداری تأییدشده، کار دستی دیگری از کاربر لازم نیست. مطابق دستور جدید کاربر، پس از تکمیل اصلاح چپ/راست هدر، ثبت وضعیت و یک کامیت، اجرای ردیف جدید متوقف می‌شود تا کاربر ادامه بخواهد.
