# SMS-06a — ذخیرهٔ مستقل نادیده و پایهٔ پاک‌سازی

فاز دادهٔ درخواست SMS-06 بر مبنای `7b782bac` اجرا شد. مدل مشترک SmsDraft فیلد nullable به نام ignoredAt و قرارداد مدت ۳۰ روز کامل دارد. migration شمارهٔ ۳۳ فقط ستون nullable را اضافه می‌کند؛ پیامک مصرف‌شدهٔ قدیمی، نادیده فرض نمی‌شود. زمان نادیده از insert و mapper عبور می‌کند تا در خواندن/بازیابی از بین نرود. ویرایش معمولی زمان نادیده را بازنویسی نمی‌کند.

سه query اضافه شدند: نادیدهٔ اتمی فقط برای پیش‌نویس مصرف‌نشده با حفظ اولین زمان، خواندن نادیدهٔ مصرف‌نشده قبل از انقضا، و حذف فقط نادیدهٔ مصرف‌نشده با موعد سپری‌شده. cutoff صریح است تا زمان آزمون کنترل‌پذیر باشد. شرط null در SQL، پیامک عادی را از پاک‌سازی خارج می‌کند.

## آزمون

هفت آزمون جدید SQLite واقعی در `IgnoredSmsPersistenceTest` پاس شدند: حفظ متن/مبلغ و مصرف‌نشدن، نادیدهٔ تکراری بدون تمدید، محافظت از مصرف‌شده و شناسهٔ ناموجود، مرز دقیق ۳۰ روز و idempotency پاک‌سازی، ویرایش با snapshot قدیمی، شناسهٔ بزرگ‌تر از Int و migration ردیف‌های قدیمی. مجموع ۹۸ آزمون database/data/domain بدون شکست پاس شد. مدرک محلی: `.artifacts/fintrack-2026-11-22/sms06-foundation-build.log` و گزارش‌های JUnit هر سه ماژول.

## مرز این کامیت

این فاز هنوز به اکشن اعلان یا UI وصل نیست؛ رفتار «نادیده» فعلی و فهرست فعلی تغییر داده نشده‌اند. SMS-06 مادر باز می‌ماند. قدم بعدی، API repository و اعتبارسنجی انقضا در ثبت اتمی، Worker پایدار، جداسازی دو فهرست و ثبت/ویرایش/عملیات گروهی در فهرست نادیده است. آزمون‌های مالی رقابت ثبت/پاک‌سازی و پذیرش واقعی روی امولاتور متعلق به فاز اتصال هستند. موفقیت کل قابلیت از آزمون پایهٔ SQL نتیجه‌گیری نمی‌شود.

Build نهایی `:app:assembleDirectDebug` به همراه سه مجموعهٔ تست در ۸ دقیقه و ۵۴ ثانیه موفق شد؛ ۶۱۳ task بررسی شد. این کامیت فقط پایهٔ داده را می‌بندد و SMS-06 مادر باز است.
