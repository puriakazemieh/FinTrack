# APP-01b — وضعیت اجرای انبردینگ

مبنای تغییر `64c7ae26` است. معرفی سینک در WelcomeStep مطابق درخواست کامنت شد. وضعیت مجوزها از remember محلی صفحه به state مشترک ViewModel منتقل شد و observer بدون درخواست مجوز، هنگام ورود و resume وضعیت سیستم را می‌خواند. انتخاب فعال/غیرفعال خواندن پیامک مستقل از مجوز سیستم نگه داشته می‌شود. اعلانِ مجاز صرفاً با سوییچ داخل اپ لغوشده جلوه داده نمی‌شود؛ سوییچ تأییدشده در انبردینگ نمایش وضعیت دارد. Android قبل از API 33 در صورت مسدودبودن اعلان، تنظیمات واقعی اعلان اپ را باز می‌کند و نتیجهٔ مثبت ساختگی برنمی‌گرداند.

Android و JVM انبردینگ در `onboarding-build.log` با build موفق آزموده شدند. مسیر JS به خطاهای قبلی IndexedDB در `core/storage/.../ImageStorageImpl.js.kt` برخورد کرد؛ `onboarding-js-build.log` مدرک مانع است و موفقیت JS ادعا نمی‌شود. actualهای iOS باید روی macOS/Xcode کامپایل و اجرا شوند؛ فعلاً تست دستی/محیط macOS باز می‌ماند. قرارداد خواندن وضعیت iOS بر اساس [مستند رسمی Apple](https://developer.apple.com/documentation/usernotifications/unnotificationsettings) نوشته شده و مجوز را با درخواست دوباره شبیه‌سازی نمی‌کند.

مدرک مبنا `onboarding-permissions-return-baseline.png` و dumpsys نشان می‌دهد مجوز پیامک داده شده بود ولی سوییچ پس از برگشت خاموش می‌شد. آزمون نسخهٔ اصلاح‌شده روی API 31 و Pixel_9_Pro_XL/API 35 با serialهای `emulator-5556` و `emulator-5558` اجرا می‌شود؛ لاگ و تصاویر `onboard31-*` و `onboard35-*` در `.artifacts/fintrack-2026-11-22/` هستند. مجوز ازقبل‌داده‌شده، رفت‌وبرگشت، حفظ انتخاب قابلیت پیامک، رد/اعطای مجوز و شروع سرد جدا بررسی می‌شوند. آزمون مسدودی سراسری با AppOps در تلاش نخست وضعیت مورد انتظار را ایجاد نکرد؛ آن تلاش پذیرش نیست و سناریو با سوییچ واقعی تنظیمات سیستم تکرار می‌شود.

API 31 فرمان تغییر permission flags را ندارد؛ برای حفظ دقیق تنظیم قبلی، روی آن وضعیت لغوشده با revoke/grant مخصوص همین اپ آزموده می‌شود. رد/اعطای دیالوگ واقعی روی API 35 انجام می‌شود. وضعیت مجوز، تنظیمات و دیتابیس هر دستگاه جدا پشتیبان‌گیری و برگردانده می‌شود. هیچ آزمونی روی گوشی شخصی انجام نمی‌شود. پذیرش Android اکنون مطابق بخش پایانی تکمیل شده است.


## پذیرش نهایی Android

نوبت‌های `onboard31-system-final.log` و `onboard35-system-final.log` رفت‌وبرگشت و وضعیت مجوز را ثبت کردند؛ `onboard31-final-settings.log` و `onboard35-final-settings.log` تغییر از تنظیمات واقعی، بازگشت و شروع سرد را پاس کردند. رسیدهای `onboard31-acceptance.json` و `onboard35-acceptance.json` موجودند. شواهد از چند نوبت است و تلاش‌های ناموفق پیش‌شرط پذیرش محسوب نشدند. APK: `820cb823b044db35e10f8ea7d171b68e5b46a3cd625a1ac16ba2e1b0f9cc7d72`.

در API 31 تفاوت بایت‌های SQLite بررسی شد و تمام جداول برابر بودند (`onboard-data-diff.cjs`). در نوبت نهایی فایل دیتابیس، preferences و وضعیت مجوز هر دستگاه نیز بازیابی شد؛ رسیدهای `onboard31-restore.json` و `onboard35-restore.json` ثبت شدند. Android این بسته به کار دستی نیاز ندارد؛ iOS و مانع JS بازند.
